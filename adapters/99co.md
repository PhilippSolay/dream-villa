# Adapter notes — 99.co Indonesia (`99co`) — **BLOCKED, not implemented**

Checked 2026-09-18 from Philipp's machine with curl, browser UA, `-sL`.

## Verdict

**Cloudflare interstitial challenge.** `GET https://www.99.co/id/sewa/villa/bali` returns
HTTP **403** with a 5 752-byte `Just a moment...` page:

```html
<title>Just a moment...</title>
<meta http-equiv="content-security-policy" content="… script-src … https://challenges.cloudflare.com …">
<noscript><span id="challenge-error-text">Enable JavaScript and cookies to continue</span></noscript>
<script … window._cf_chl_opt = {cFPWv: 'g', cH: '…'} …>
```

That is bot detection; clearing it means running Cloudflare's JS challenge and carrying its
cookie, which CLAUDE.md and SPEC §6 rule out. Not attempted. No adapter file exists; the
registry has no `99co` entry.

Note the challenge is served on the *first* request, so a Playwright run (`PLAYWRIGHT=1`) is
not obviously a fix either — it would be solving the same challenge, just with a real engine.
Leave it. Individual 99.co URLs can still go through the `inbox` adapter from Philipp's own
browser session.

## robots.txt (fetched fine — 200, 3 388 bytes)

The `User-agent: *` group is permissive about the SEO search paths and blocks the plumbing:

```
Disallow: /api            Disallow: /id/ajax/  /id/ajax2/  /id/cari/   Disallow: /id/amp/
Disallow: /id/p/          Disallow: /id/*?pageSize=      Disallow: /id/*?listingType
Disallow: /id/*?tipe_properti=     Disallow: /id/*?urut=*
Disallow: /id/property/ajax-map    Disallow: /id/property/ajax-similar-property-list
```

Two things a future adapter must respect: `/id/cari/` (the query-string search) is **disallowed**,
so only the pretty `/id/sewa/{type}/{location}` paths may be crawled, and the sort/page-size
query parameters are disallowed too. `trovitBot` is banned outright; `rogerbot`/`dotbot` get
`Crawl-delay: 3`. There is no `Crawl-delay` for `*` — our 1 req/s stands.
